## Telco Churn – End-to-End ML Project
### Purpose

Build and ship a full machine-learning solution for predicting customer churn in a telecom setting—from data prep and modeling to a Dockerized Streamlit web UI deployed on Render.

### Problem solved & benefits

- Faster decisions: Predicts which customers are likely to churn so teams can act before they leave.
- Operationalized ML: Model is accessible via a REST API and a simple UI; anyone can test it without notebooks.
- Repeatable delivery: CI/CD + containers mean every change can be rebuilt, tested, and redeployed in a consistent way.
- Traceable experiments: MLflow tracks runs, metrics, and artifacts for reproducibility and auditing.

### What I built

- Data & Modeling: Feature engineering + XGBoost classifier; experiments logged to MLflow.
- Model tracking: Runs, metrics, and the serialized model logged under a named MLflow experiment.
- Inference service: FastAPI app exposing /predict (POST) and a root health check /.
- Web UI: Streamlit interface for quick, shareable manual testing.
- Containerization: Docker image running Streamlit on Render's assigned port.
- CI/CD: GitHub Actions builds and pushes the image to Docker Hub, then optionally triggers a Render deploy hook.
- Deployment: Render runs the published Docker image as a web service.

### Deployment flow (high-level)

- Push to main → GitHub Actions builds the Docker image and pushes it to Docker Hub.
- GitHub Actions calls the Render deploy hook when `RENDER_DEPLOY_HOOK_URL` is configured.
- Render pulls the new image and starts Streamlit using the `PORT` environment variable.
- Users open the Render service URL to use the Streamlit interface.

### Render setup

Create a Render Web Service using **Existing Image** and configure it with:

- Image: `docker.io/<your-dockerhub-username>/telco-churn:latest`
- Port: `8501`
- Health check path: `/_stcore/health`

Add these GitHub repository secrets:

- `DOCKERHUB_USERNAME`
- `DOCKERHUB_TOKEN`
- `RENDER_DEPLOY_HOOK_URL` (optional, generated by Render)

### Roadblocks & how we solved them

Streamlit health checks

- Render can check `/_stcore/health` to confirm that the Streamlit process is ready.

Module import error in container (ModuleNotFoundError: serving)

- Cause: Python path in the image didn’t include src/.
- Fixes: Set `PYTHONPATH=/app/src` in the Dockerfile and run the Streamlit module from the project root.

Model loading error

- Cause: The serving image did not contain the selected MLflow model or feature schema.
- Fixes: The Dockerfile copies both into `/app/model`.

Local testing vs. Render paths

- Cause: Render assigns the application port dynamically.
- Fixes: Streamlit reads `PORT`, while local runs default to port `8501`.
